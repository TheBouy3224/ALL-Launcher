## Mod Doctor findings

### Current 2.5.3 source

- No current source file or symbol matching `ModDoctor`, `ModDoctorPlanSolver`, or a mod-doctor package was found under `ZalithLauncher/src/main/java`.
- `AllModReader` reads local metadata and returns a `notMod` fallback on parse failure; it does not produce a launch-blocking mod report.
- `InstalledModMatcher` fingerprints local files and matches them to Modrinth/CurseForge projects/versions. Its current use is installed detection and Auto Dependencies duplicate guarding, not conflict diagnosis or repair.
- `PlatformDependencyType` includes `REQUIRED`, `OPTIONAL`, `INCOMPATIBLE`, `EMBEDDED`, `TOOL`, and `INCLUDE`, but current install automation only expands `REQUIRED` dependencies.
- `GameLaunchFlow` performs account validation and Minecraft file verification; it does not validate the mod graph before launch.
- `GameInstaller` has client JSON/JAR overwrite backup/revert, which is game-install rollback, not mod-instance backup.

### Old ALL reference

`D:/All New/ZalithLauncher2/ZalithLauncher/src/main/java/com/movtery/zalithlauncher/game/version/mod/doctor/` contains:

- `ModDoctor.kt`: local metadata constraint checks, provider graph resolution, required/incompatible handling, candidate replacement, rescan, and repair execution.
- `ModDoctorPlanSolver.kt`: deterministic joint candidate-plan selection and validation.
- `SodiumIrisConflictRegressionTest.kt`: provider/local metadata regression coverage.
- `game/version/backup/InstanceBackupManager.kt` and backup UI: related instance backup support.

These files prove an older ALL implementation exists, but they are **reference-only**. They are not part of the current 2.5.3 base and were not ported or modified during this audit.

- Account persistence plus Microsoft OAuth/Xbox/Minecraft validation and refresh.
- Minecraft version installation, loader installation/update, deletion, isolation, and game-file verify/repair.
- Modrinth and CurseForge download/install with required dependency resolution and duplicate detection.
- Local mod metadata reading, enable/disable/delete/update, and installed provider fingerprint matching.
- Runtime import/selection/removal and Java version/architecture/broken-runtime detection.
- Task/download engine with progress, concurrency, failover, bounded retry, checksum verification, and atomic commit.
- Controls editor/layout import-export and gamepad remapping.

- File manager, game-data screens, archive/trash/edit/search operations.
- Crash log persistence, game/launcher error screens, log share/upload/restart/exit.

## NEXT FEATURE CANDIDATES

Only capabilities audited as **PARTIAL** are candidates; nothing here is implemented by this audit.

1. **Pre-launch mod validation gate** — detect missing required dependencies, wrong loader/MC version, incompatible mods, duplicate logical mods, and unreadable/corrupt mod files before launch.
2. **Mod Doctor V1** — read-only report first; use current `AllModReader`, local dependency metadata, and installed matching before considering repair.
3. **Mod repair execution** — only after a report is proven: bounded replacement/disable flow, explicit failure state, and backup/rollback policy.
4. **First-class installed-mod version change** — allow selecting a specific compatible provider version for one installed mod, including safe replacement semantics.
5. **Java pre-launch remediation** — detect selected-runtime failure before launch and offer a bounded reselect/re-import path; automatic repair/download remains a separate scope decision.
6. **Actionable crash diagnosis** — classify known launch/mod/runtime failure signatures and link only to verified next actions; do not claim repair automatically.
7. **Durable download resume** — persist resumable transfer state across process interruption instead of deleting `.part` on failed attempt.

## Audit conclusion

**PASS** — current 2.5.3 source was inspected deeply enough to avoid duplicating existing upstream systems. The strongest genuine gap is not Auto Dependencies: it is pre-launch mod validation/Mod Doctor and its repair policy. No source code was modified, no build was run, and no feature was implemented by this audit.
